# 法律风控 DeepResearch 评测系统工程方案

建议将当前 `LLM_as_Judge` 做成一个独立的后处理评测系统，工程形态为：

```text
LegalEvalOrchestrator 评测编排器
        │
        ├── 数据读取类工具
        ├── 报告解析类工具
        ├── 规则引擎类工具
        ├── 引用与证据链核验工具
        ├── 过程日志分析工具
        ├── Gold 标准比对工具
        ├── LLM_as_Judge 语义评审 Agent
        ├── 后置一致性检查工具
        └── 评测结果存储工具
```

它应该是**固定流程型 Eval Agent**，而不是自由行动型 Agent。
也就是说，LLM 只负责那些必须依赖语义判断的部分；凡是能用规则、字段、ID、正则、source 对齐完成的判断，都应由确定性工具完成。

你当前的测评方案本身强调 DeepResearch 评估要从三类目标出发：**研究质量、研究过程、业务效果**，并将它们拆成可量化指标和固定流程。 当前项目又已经具备 DeepResearch V2、checkpoint、state_json、SSE 过程日志和最终报告等结构，适合在报告完成后追加一个独立评测编排器。项目文档中也说明 `/research/stream` 会通过 DeepResearch V2 生成报告，并在运行中保存状态和最终结果。

## 1.2 是否创建成 Agent？

需要创建成 Agent，但它应命名为：

```text
LegalEvalOrchestrator
```

或者：

```text
LegalRiskEvalJudgeAgent
```

不过这里的 “Agent” 不是自由规划型 Agent，而是**评测编排器**。

它不应该自己决定要不要查法条、要不要跳过规则、要不要放行报告。它只按照固定流程调用工具：

```text
加载报告
→ 解析报告
→ 抽取 claim
→ 规则引擎预检
→ 引用核验
→ 证据链核验
→ 法域版本核验
→ 过程日志分析
→ Gold 覆盖度比对
→ LLM Judge 复核
→ 后置一致性检查
→ 聚合评分
→ 保存评测结果
```

---

## 1.3 与原 DeepResearch 的关系

不要替换原来的 `CriticMaster`。

两者职责不同：

| 模块                      | 所属阶段    | 作用                  |
| ----------------------- | ------- | ------------------- |
| `CriticMaster`          | 报告生成过程中 | 帮助 agent 自我修订       |
| `LegalEvalOrchestrator` | 报告生成完成后 | 独立评估这份报告质量          |
| `LLM_as_Judge`          | 评测流程内部  | 对规则工具无法完全判断的维度做语义评分 |

当前 DeepResearch V2 已经有 `ChiefArchitect → DeepScout → DataAnalyst → CodeWizard → LeadWriter → CriticMaster` 的流程，后续法律风控 Agent 会在这个流程内完成报告生成。 评测系统应该在 `research_complete` 之后运行，而不是插入原生成链路。

# 二、总体运行逻辑

## 2.1 单报告评测流程

```text
输入：session_id 或 candidate_report + task_meta
        │
        ▼
1. CheckpointLoader 读取 final_report / state_json / logs
        │
        ▼
2. TaskLoader 读取 benchmark task / gold 标准
        │
        ▼
3. ReportParser 解析报告结构
        │
        ▼
4. ClaimExtractor 抽取关键结论
        │
        ▼
5. RuleEngine 执行红线预检
        │
        ▼
6. CitationVerifier 核验引用
        │
        ▼
7. EvidenceVerifier 核验证据链
        │
        ▼
8. JurisdictionChecker 核验法域与版本
        │
        ▼
9. ProcessTraceAnalyzer 分析研究过程
        │
        ▼
10. GoldComparator 比对关键要点覆盖
        │
        ▼
11. LLMJudge 进行语义评分
        │
        ▼
12. PostChecker 检查 Judge 是否自相矛盾
        │
        ▼
13. Aggregator 汇总三大目标分和最终结论
        │
        ▼
14. ResultStore 保存 eval_result
```

---

## 2.2 批量评测流程

用于 prompt、模型、检索策略、Agent 改动后的回归测试。

```text
benchmark_tasks.jsonl
        │
        ▼
for each task:
    调用 /research/stream 或读取已有 session
    生成/读取 final_report
    调用 LegalEvalOrchestrator
    保存 eval_result
        │
        ▼
生成 batch_eval_summary.json
        │
        ▼
输出版本对比：
    overall_score
    research_quality
    research_process
    business_effect
    fatal_error_rate
    hallucination_rate
    citation_coverage
    evidence_chain_score
```

这与原测评方案的路线一致：输入任务和配置，调用 deepresearch pipeline，得到报告与过程日志，再调用独立 LLM Judge，并抽样做人类评审。

# 三、核心数据结构

## 3.1 LegalEvalInput

```python
class LegalEvalInput(BaseModel):
    eval_id: str
    task_id: Optional[str] = None
    session_id: Optional[str] = None

    task_meta: Dict[str, Any] = Field(default_factory=dict)
    candidate_report_markdown: str

    state_json: Dict[str, Any] = Field(default_factory=dict)
    process_events: List[Dict[str, Any]] = Field(default_factory=list)

    source_index: List[Dict[str, Any]] = Field(default_factory=list)
    risk_items: List[Dict[str, Any]] = Field(default_factory=list)
    evidence_chain: List[Dict[str, Any]] = Field(default_factory=list)

    gold_reference: Optional[Dict[str, Any]] = None
    run_meta: Dict[str, Any] = Field(default_factory=dict)
```

说明：

```text
candidate_report_markdown：最终法律风控报告
state_json：DeepResearch 全局状态
source_index：法规、案例、合同、处罚、内部制度等来源
risk_items：风险项
evidence_chain：证据链
gold_reference：Gold 标准，可为空
```

当前项目已有 `ResearchCheckpoint`，其中保存 `session_id`、`query`、`phase`、`iteration`、`state_json`、`ui_state_json`、`final_report`、`status`、`error_message`，这正好可以作为 `LegalEvalInput` 的主要数据来源。

## 4.5 `LegalRuleEngineTool`

### 文件

```text
backend/app/service/legal_eval/tools/rule_engine.py
```

### 职责

执行硬红线检查。

### 第一版必须实现的 fatal 规则

```text
MISSING_DISCLAIMER
DETERMINISTIC_LEGAL_ADVICE
FABRICATED_LAW_OR_CASE
WRONG_JURISDICTION
EXPIRED_LAW_AS_CURRENT
UNSUPPORTED_HIGH_RISK_CONCLUSION
```

### 核心正则

```python
DISCLAIMER_RE = r"(不构成(正式)?法律意见|仅供.*参考|应咨询(执业)?律师|需由.*律师复核|需由.*法务复核)"

ABSOLUTE_ADVICE_RE = r"(可以直接|无需.*复核|肯定|必然|一定|保证).{0,20}(签署|胜诉|败诉|违法|无效|解除|裁员|付款|放行)"

LAW_CIT_RE = r"《[^》]{2,50}》第[一二三四五六七八九十百千万0-9]+条"

CASE_NO_RE = r"（\d{4}）[^\\s，。；、]{1,40}号"
```

## 4.7 `EvidenceChainVerifierTool`

### 文件

```text
backend/app/service/legal_eval/tools/evidence_verifier.py
```

### 职责

检查风险项是否有完整证据链。

### 规则

```text
1. 每个 risk_item 最好有 evidence_ids。
2. 每个 evidence_id 必须能匹配 evidence_chain。
3. evidence_chain 中每个 evidence 必须有 source_id。
4. 高风险/重大风险必须至少有事实依据。
5. 高风险/重大风险最好同时有规范依据。
```

### 输出

```json
{
  "evidence_chain_complete": true,
  "risk_with_evidence_ratio": 0.91,
  "high_risk_dual_basis_ratio": 0.8,
  "unsupported_high_risk_items": [],
  "weak_evidence_risk_items": []
}
```

# 五、评测编排器设计

## 5.1 `LegalEvalOrchestrator`

### 文件

```text
backend/app/service/legal_eval/eval_orchestrator.py
```

### 职责

统一编排所有工具。

### 伪代码

```python
class LegalEvalOrchestrator:
    def __init__(
        self,
        checkpoint_loader: CheckpointLoaderTool,
        task_loader: EvalTaskLoaderTool,
        report_parser: ReportParserTool,
        claim_extractor: ClaimExtractorTool,
        rule_engine: LegalRuleEngineTool,
        citation_verifier: CitationVerifierTool,
        evidence_verifier: EvidenceChainVerifierTool,
        jurisdiction_checker: JurisdictionVersionCheckerTool,
        retrieval_metrics: RetrievalMetricsTool,
        process_trace_analyzer: ProcessTraceAnalyzerTool,
        gold_comparator: GoldComparatorTool,
        actionability_checker: ActionabilityCheckerTool,
        llm_judge: LLMJudgeAgent,
        post_checker: PostCheckTool,
        result_store: EvalResultStoreTool,
    ):
        ...

    async def evaluate(self, request: LegalEvalRequest) -> LegalEvalResult:
        state = LegalEvalState(eval_input=await self._build_eval_input(request))

        state.parsed_report = self.report_parser.parse(
            state.eval_input.candidate_report_markdown
        )

        state.extracted_claims = await self.claim_extractor.extract(
            report_markdown=state.eval_input.candidate_report_markdown,
            parsed_report=state.parsed_report,
            task_meta=state.eval_input.task_meta
        )

        state.rule_engine_result = self.rule_engine.run(
            task_meta=state.eval_input.task_meta,
            report_markdown=state.eval_input.candidate_report_markdown,
            source_index=state.eval_input.source_index,
            risk_items=state.eval_input.risk_items,
            evidence_chain=state.eval_input.evidence_chain,
            claims=state.extracted_claims,
            gold_reference=state.eval_input.gold_reference
        )

        state.citation_result = self.citation_verifier.verify(
            report_markdown=state.eval_input.candidate_report_markdown,
            source_index=state.eval_input.source_index,
            claims=state.extracted_claims
        )

        state.evidence_result = self.evidence_verifier.verify(
            risk_items=state.eval_input.risk_items,
            evidence_chain=state.eval_input.evidence_chain,
            source_index=state.eval_input.source_index
        )

        state.jurisdiction_result = self.jurisdiction_checker.verify(
            task_meta=state.eval_input.task_meta,
            source_index=state.eval_input.source_index,
            report_markdown=state.eval_input.candidate_report_markdown
        )

        state.process_result = self.process_trace_analyzer.analyze(
            state_json=state.eval_input.state_json,
            process_events=state.eval_input.process_events
        )

        state.retrieval_result = self.retrieval_metrics.score(
            source_index=state.eval_input.source_index,
            gold_reference=state.eval_input.gold_reference,
            process_result=state.process_result
        )

        state.gold_comparison_result = self.gold_comparator.compare(
            report_markdown=state.eval_input.candidate_report_markdown,
            gold_reference=state.eval_input.gold_reference,
            claims=state.extracted_claims
        )

        state.actionability_result = self.actionability_checker.check(
            report_markdown=state.eval_input.candidate_report_markdown,
            risk_items=state.eval_input.risk_items
        )

        state.llm_judge_result = await self.llm_judge.score(
            eval_input=state.eval_input,
            parsed_report=state.parsed_report,
            claims=state.extracted_claims,
            rule_engine_result=state.rule_engine_result,
            citation_result=state.citation_result,
            evidence_result=state.evidence_result,
            jurisdiction_result=state.jurisdiction_result,
            retrieval_result=state.retrieval_result,
            process_result=state.process_result,
            gold_comparison_result=state.gold_comparison_result,
            actionability_result=state.actionability_result,
        )

        state.post_check_result = self.post_checker.check(
            rule_engine_result=state.rule_engine_result,
            llm_judge_result=state.llm_judge_result,
            evidence_result=state.evidence_result,
            citation_result=state.citation_result
        )

        state.final_result = aggregate_final_result(state)

        self.result_store.save(state.final_result)

        return LegalEvalResult(**state.final_result)
```

### Gate 规则

```python
def decide_gate(final_result: dict) -> dict:
    fatal_errors = final_result.get("fatal_errors", [])
    goal_scores = final_result.get("goal_scores", {})
    dimensions = final_result.get("dimensions", {})
    post_check = final_result.get("post_check_result", {})

    if fatal_errors:
        return {
            "pass_gate": "fail",
            "release_ready": False,
            "requires_human_review": True,
            "reason": "存在 fatal_errors"
        }

    if not post_check.get("post_check_pass", True):
        return {
            "pass_gate": "fail",
            "release_ready": False,
            "requires_human_review": True,
            "reason": "Judge 输出与规则检查结果不一致"
        }

    if goal_scores.get("research_quality", 0) < 7.5:
        return {
            "pass_gate": "revise",
            "release_ready": False,
            "requires_human_review": True,
            "reason": "研究质量分不足"
        }

    if dimensions.get("legal_factuality", {}).get("score", 0) < 4.0:
        return {
            "pass_gate": "fail",
            "release_ready": False,
            "requires_human_review": True,
            "reason": "法律事实正确性不足"
        }

    if dimensions.get("evidence_chain", {}).get("score", 0) < 4.0:
        return {
            "pass_gate": "revise",
            "release_ready": False,
            "requires_human_review": True,
            "reason": "证据链完整性不足"
        }

    if final_result.get("overall_score", 0) >= 8.5:
        return {
            "pass_gate": "conditional_pass",
            "release_ready": False,
            "requires_human_review": True,
            "reason": "法律风控报告建议人工复核后使用"
        }

    if final_result.get("overall_score", 0) >= 7.5:
        return {
            "pass_gate": "revise",
            "release_ready": False,
            "requires_human_review": True,
            "reason": "可修订后复评"
        }

    return {
        "pass_gate": "fail",
        "release_ready": False,
        "requires_human_review": True,
        "reason": "整体质量不足"
    }
```

法律风控场景下，第一阶段建议几乎不要输出 `release_ready=true`。即便高分，也建议是：

```json
{
  "pass_gate": "conditional_pass",
  "release_ready": false,
  "requires_human_review": true
}
```

### 规则引擎快速评测


## schemas.py 先定义空壳

```python
from typing import Any, Dict, List, Optional
from pydantic import BaseModel, Field


class LegalEvalRequest(BaseModel):
    session_id: Optional[str] = None
    task_id: Optional[str] = None
    candidate_report_markdown: Optional[str] = None
    task_meta: Dict[str, Any] = Field(default_factory=dict)
    source_index: List[Dict[str, Any]] = Field(default_factory=list)
    risk_items: List[Dict[str, Any]] = Field(default_factory=list)
    evidence_chain: List[Dict[str, Any]] = Field(default_factory=list)
    gold_reference: Optional[Dict[str, Any]] = None
    use_llm_judge: bool = True
    save_result: bool = True


class LegalEvalResult(BaseModel):
    eval_id: str
    overall_score: float = 0.0
    goal_scores: Dict[str, float] = Field(default_factory=dict)
    dimensions: Dict[str, Any] = Field(default_factory=dict)
    fatal_errors: List[Dict[str, Any]] = Field(default_factory=list)
    warnings: List[Dict[str, Any]] = Field(default_factory=list)
    auto_checks: Dict[str, Any] = Field(default_factory=dict)
    metrics: Dict[str, Any] = Field(default_factory=dict)
    decision: Dict[str, Any] = Field(default_factory=dict)
    notes: Dict[str, Any] = Field(default_factory=dict)
```

# 九、评分映射

## 9.1 维度分

每个维度 0-5 分：

```text
5：优秀，可直接作为高质量工作底稿
4：良好，小修可用
3：基本可用，但有明显补充空间
2：质量不足，需要大修
1：严重不足，仅有少量参考价值
0：红线错误或完全不可用
```

## 9.2 三大目标分

```text
research_quality = 0-10
research_process = 0-10
business_effect = 0-10
```

换算方式：

```python
goal_score_0_10 = weighted_dimension_score_0_5 * 2
```

## 9.3 总分

```python
overall_score = (
    research_quality * 0.60
    + research_process * 0.25
    + business_effect * 0.15
)
```

## 9.4 放行规则

```text
fatal_errors 非空：fail
post_check 不通过：fail
research_quality < 7.5：revise
legal_factuality < 4/5：fail
evidence_chain < 4/5：revise
overall >= 8.5：conditional_pass
overall 7.5-8.5：revise
overall < 7.5：fail
```

# 十二、最关键的防跑偏检查

```text
1. legal_eval 是独立评测模块，不侵入生成流程。

8. /research/stream 没有被破坏。
9. /hello 正常。
10. compileall 通过。
```

这套工程形态的核心思想是：

```text
LegalEvalOrchestrator 负责流程编排；
RuleEngine 负责硬红线；
Verifier 工具负责事实、引用、证据链核验；
Process 工具负责研究行为评估；
LLMJudge 负责语义质量判断；
PostCheck 负责防止 Judge 自相矛盾；
Aggregator 负责最终分数和放行决策。
```
